Kashif Progress Summary

Iteration 1: Authentication · 19–23 October 2026

1. Environment and Architecture

  • Containerised the system with Docker Compose: PostgreSQL 18 database, FastAPI (Python 3.13) backend, and React + Vite frontend.
  • Kept the database off the public network with no published ports. Development access is bound to 127.0.0.1 only.
  • Stored secrets in .env (excluded from Git) and added a .env.example template.
  • Connected the frontend to the backend through a Vite proxy, so the browser treats them as a single origin.

2. Database

  • Created a users table with UUID primary keys, unique email addresses, first and last names, Bahraini mobile numbers in E.164 format (+973), password hashes, roles (citizen, employee, admin), active status, and creation time.
  • Applied data minimisation by collecting only the information the system needs.

3. Authentication and Authorisation (Backend)

  • Added registration with server-side validation using Pydantic.
  • Implemented login with Argon2id password hashing.
  • Issued JWT access tokens using HS256 with a 30-minute expiry, stored in an HttpOnly, SameSite=Strict cookie.
  • Added a /me endpoint and a get_current_user dependency that verifies the token and re-checks the user in the database.
  • Added a POST logout endpoint that clears the cookie.
  • Implemented role-based access control with a reusable require_role() dependency.
  • Added a create_admin CLI script so the first admin can only be created on the server, never through the public API.

4. Security Controls (OWASP Top 10: 2025)

OWASP category Control implemented
A01: Broken Access Control extra="forbid" blocks mass assignment, so role: admin returns 422. Roles are fixed server-side, RBAC returns 403 when access is denied, and UUIDs reduce IDOR risk.
A04: Cryptographic Failures Argon2id password hashing with a per-user salt; sensitive data is not placed in URLs because forms use POST.
A05: Injection Database queries use parameterisation through the SQLAlchemy ORM. React escapes output by default, helping prevent XSS.
A07: Authentication Failures Generic login errors and a dummy hash help prevent user enumeration and timing attacks. Passwords must be at least 12 characters. Tokens are signed and expiring, with the algorithm pinned to block alg: none.
A10: Mishandling of Exceptional Conditions Stack traces are kept in server logs and are never returned to the client.

5. Frontend

  • Connected login and registration pages to the API, with protected and guest routes.
  • Added a password-strength meter, show/hide toggle, and live password-match check.
  • Created a design system with tokens, components, and per-feature CSS, including light and dark modes.
  • Improved accessibility with labels, ARIA attributes, keyboard focus styles, reduced-motion support, and WCAG AA colour contrast.
  • Added an auto-rotating showcase featuring Bahraini landmarks.

6. Testing Evidence

  • Duplicate email returns 409; a short password returns 422; and an injected role: admin returns 422.
  • Wrong password and unknown email return the same 401 response.
  • document.cookie returns an empty string, confirming the cookie is HttpOnly.
  • A tampered token and a missing token each return 401.
  • A citizen calling a staff endpoint gets 403; an admin gets 200.
